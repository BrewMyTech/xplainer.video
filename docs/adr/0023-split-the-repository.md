# 0023. Split the repository: the local tier is public and open source here, the hosted tier is relocated to a private repository

- Status: accepted
- Date: 2026-09-06
- Deciders: @rishavanand
- Settled by: owner decision, taken against the unresolved Remotion question that ADR 0015
  left open and that [ADR 0022](0022-open-source-the-published-packages.md) sharpened rather
  than answered — "the local product is the one we can ship without asking anyone's
  permission"

## Context and Problem Statement

[ADR 0022](0022-open-source-the-published-packages.md) put the six published packages under
Apache-2.0. It was explicit that an open-source **licence** is not a public **repository**,
and that making this repository public was a separate decision it did not make. This record
makes it.

Three things were true at the same time, and only two of them could stay in one repository.

**First, the local tier is finished being a legal question.** ADR 0022's central move was
"declare Remotion rather than bundle it": `@xplainer/render-core` scaffolds a Remotion
workspace whose `package.json` names Remotion, and the *user's own* install fetches Remotion
under Remotion's terms, on the user's own machine. The user is plainly the operator. There is
nobody to ask for permission, and nothing about the local tier is waiting on an answer.

**Second, the hosted tier is not.** Remotion's Terms forbid operating "a rendering service
that allows end-users to bring or upload their own Remotion code" absent "prior explicit and
written approval". When our servers render, **we** operate Remotion — regardless of what
licence our wrapper carries. The AI carve-out is conditioned on the code being "initially
generated by your service", and our authorship chain may fail that condition: under
[ADR 0007](0007-mcp-tool-contract-and-put-source.md) the TSX is generated by the *customer's*
agent, on the customer's machine, by a skill we publish. ADR 0022 recorded this in its own
words — the hosted members are "proprietary, unpublished, and on the wrong side of an
unanswered vendor question" — and declined to resolve it. It is still unanswered today. The
vendor email drafted for it has not been sent.

**Third, a repository is public or it is not.** There is no half-public git history. Keeping
one repository forces a single answer to a question that has two different correct answers:
the local tier should be readable by anyone, and the hosted tier should not be readable at
all while a live commercial question about it is open. Publishing a repository that contains
the hosted control plane, its pricing, its quota design and an internal risk memo about a
supplier is a worse outcome than either tier deserves.

The forcing function is that the local tier is *ready* and is being held back by the tier it
shares a directory with.

## Decision Drivers

- **The local tier ships without permission from anyone; the hosted tier does not.** That is
  a difference in kind, not in maturity, and it should be visible in the repository layout.
- **A public repository is a distribution event that cannot be retracted.** Everything a
  reader can see stays seen. The set of files that must never become public is known, small
  and enumerable, and it is cheaper to move them than to police them.
- **The tier boundary has been machine-checked since the first commit**
  ([ADR 0003](0003-tier-boundary-and-open-later-plan.md)), for exactly this. If it held, the
  split is a directory move. If it did not, no amount of care at split time would help.
- **The hosted tier is deferred, not cancelled.** Any shape of split that reads as
  abandonment is wrong on the facts and would have to be un-said later.
- **Reversibility.** Whatever is done here should be undoable by moving directories back, not
  by reconstructing anything.

## Considered Options

1. **Split into a public local repository and a private hosted one.**
2. **One repository, made public with the hosted tier inside it.**
3. **One repository, kept private indefinitely.**
4. **Cancel the hosted tier and delete its work.**

## Decision Outcome

**Chosen: option 1.** This repository — `BrewMyTech/xplainer.video` — becomes the public,
open-source local product: the CLI daemon, the optional desktop client, the render core, the
protocol, the agent skill, and the storage-and-delivery infrastructure that release artefacts
and first-run downloads are served from. The hosted tier is **relocated** to the private
repository `BrewMyTech/xplainer-hosted`, which carries the complete history of this
repository — all eight commits, every file — as it stood at
`ea4ff39f012166dad59022aae74eee0015eb5d55`.

**Nothing was destroyed by this split.** Every file removed here exists there, at that commit,
with its history. That is the property that makes the reduction safe, and it is the property
that makes it reversible.

### Why not option 2 — public with the hosted tier inside

It publishes, permanently, three things that have no public purpose and one that is actively
harmful: the hosted control plane's design, its pricing and quota model, an internal risk
assessment of a live commercial question with a supplier, and an unsent negotiating position
addressed to that supplier. The last of those is the one that decides it. Publishing a
negotiating position before sending it is strictly worse than not publishing it, and it
cannot be walked back.

### Why not option 3 — stay private

Apache-licensed packages publish to npm from a private repository perfectly well, so option 3
is not incoherent. It fails on what open source is *for* here: a user who installs
`@xplainer/cli` and wants to know what runs on their machine cannot read it; a contributor has
nowhere to send a patch; and ADR 0022's shipped `.d.ts` files cite ADR numbers that no
installer can resolve. Option 3 keeps the licence and gives up everything the licence was
chosen to enable.

### Why not option 4 — cancel

The hosted work is correct on its own terms and its blocking question is a vendor's answer,
not a design flaw. Deleting it would destroy a settled option set — four job-queue options,
two storage options, a costed VM-versus-Lambda comparison — that would have to be re-derived
the day the vendor answers. **The hosted tier is deferred pending a written answer from
Remotion AG. It is not cancelled, and this record is the reason no reader should conclude
otherwise.**

**Decision records relocated** (see the next section for why each one could not stay).

**Documents removed to the private repository:**

| Document | Why it could not stay |
|---|---|
| `.omc/specs/deep-interview-xplainer-monorepo-init.md` | Absolute local paths; the private sibling repository's name; a free-and-paid plan shape and a vendor price list in its own Goal and Stack sections |
| `.omc/plans/ralplan-xplainer-monorepo-init.md` | The same paths, twenty-two times, inside 172 KB of hosted build plan and interview transcript |
| `docs/open-questions-resolution.md` | An internal risk memo: it states in the repository's own voice that a Remotion permission condition "is a permission condition the local tier may not meet" and marks it **UNRESOLVED**; it carries margin arithmetic against our own free tier; and it ends with an **unsent** draft email to Remotion AG, with the questions framed to elicit favourable answers. It is research, not a decision record, so no immutability convention protects it — and publishing a negotiating position before sending it is the one move here with no upside |

Scrubbing the first two was considered and rejected: the absolute paths are the *smallest*
problem in either file, and a scrub that fixed them would leave the commercial planning
untouched.

The two planning documents are the provenance that the decision records cite, at section
granularity, in bodies that are immutable. Removing them without saying where they went would
make every one of those citations unverifiable. The replacement is a Provenance section in
[`README.md`](README.md) naming the private repository, both paths inside it, and the commit
SHA above — because `git show <sha>:<path>` resolves for anyone with access and a bare
repository name does not. **No in-record citation was edited.** `plan §4 S2.8` still resolves;
the index is the one place that explains where.

The phase-0 acceptance criteria left with the spec and the plan, and 52 comments, test names
and CI step names in this repository cite them by id. They are rehomed verbatim, under their
existing ids, in [`../acceptance-criteria.md`](../acceptance-criteria.md), with tombstone rows
for the ones that judged hosted work.

## Consequences

### What is given up

- **One command no longer covers the product.** `pnpm turbo build lint typecheck test` now
  covers nine members instead of twelve, and nothing in either repository builds both tiers
  together. A change to `packages/protocol` that breaks `apps/api` is discovered in the other
  repository's CI, not in this one.
- **The npm tier check's real-graph half is vacuous here.** No `hosted` member remains, so
  `pnpm lint:tiers` cannot produce a violation from the real graph. What it still enforces is
  that every member declares a tier (exit 2 otherwise), and the proof that the rule *can* fail
  is now carried entirely by the synthetic fixture in `packages/config/src/tiers.test.ts`.
  This is recorded in ADR 0003's 2026-09-06 note rather than left to be discovered.
- **The Python import-linter contract retires.** `apps/api` was the only `hosted` Python
  module; with it gone the contract has no forbidden target, and a contract that cannot be
  violated proves nothing. The `[tool.importlinter]` block, the `import-linter` dependency,
  the CI step and `apps/api/tests/test_tier_boundary.py` go together. The Biome specifier ban
  is deliberately **kept** — with its message retargeted at the private repository — because
  it is now the only mechanism that stops this repository re-acquiring a dependency on the
  relocated tier.
- **The decision provenance is no longer readable by a public reader.** Every ADR cites an
  interview round and a plan section. Those citations now resolve only for someone with access
  to the private repository. The Provenance section makes that explicit instead of leaving a
  broken relative link, but it does not make the documents readable.
- **Five ADR numbers become gaps.** A reader of 0001–0023 will find 0010, 0012, 0014, 0015 and
  0017 missing. Tombstone rows are the mitigation; they are not the same as having the records.
- **The `.d.ts` ADR-citation defect that ADR 0022 booked gets slightly larger, not smaller.**
  With the ADRs public, most cited numbers become resolvable for the first time — except the
  five that left, which do not. ADR 0022's ruling stands: the fix is editorial, at source.
- **`docs/ROADMAP.md` lost two phases.** Phases 3 and 4 were hosted end to end. They are
  relocated to the private repository's own roadmap, not deleted, and the local roadmap is
  renumbered around what remains. A roadmap is not a decision record, which is why rewriting
  it was permitted where rewriting an ADR was not.

### What is not given up

- **The tier boundary itself.** Unchanged, still declared per member, still checked. It is
  what made this split a directory move.
- **The published packages.** Apache-2.0, unchanged, same six packages, same npm scope.
  ADR 0022 is not modified by this record.
- **The hosted design.** Intact, at `ea4ff39f`, in a repository that can be worked in today.

### This is reversible

Deliberately so, and cheaply:

- The private repository holds this repository's complete history at `ea4ff39f`. Reversing the
  split is restoring three directories, the root `pyproject.toml`'s workspace member and its
  import-linter contract, three `ignore` entries in `.changeset/config.json`, and five ADR
  files — not a reconstruction.
- Nothing was rewritten, only moved and marked. The relocated records' bodies are byte-identical
  to what they were; the removed ones are byte-identical in the private repository.
- The reversal has a trigger that is written down rather than left to mood: **a written answer
  from Remotion AG on the rendering-service question.** If it permits the hosted shape, the
  hosted tier resumes where it stopped. If it does not, the hosted tier is redesigned or
  dropped as a product decision, and *that* is the record that would cancel it — not this one.

### What this record does not do

1. **It does not answer the Remotion question.** It routes around it. The vendor email is still
   unsent, and ADR 0015 is still `proposed` — in the other repository.
2. **It does not relicense anything.** The six published packages are Apache-2.0 (ADR 0022);
   `apps/desktop`, `packages/config`, `services/tts-sidecar`, `docs/`, `infra/` and `scripts/`
   are covered by `LICENSE` Part Two and are **not** open source today. A repository that is
   public is not thereby open source, and this record must not be read as having relicensed the
   remainder. Doing so is a separate decision and it is open work; `LICENSE` Part Two also still
   names three directories that this split removed, and it should be corrected before the
   repository is made public.
3. **It does not publish the plugin bundles.** Both `.mcp.json` files pointed at the hosted MCP
   endpoint, which this repository no longer describes. Retargeting them at the local daemon is
   required by the split (a marketplace fetch is not retractable, and publishing a dead URL
   ships an install that silently does nothing) — but `xplainer mcp` is a stub that exits 2
   until roadmap phase 1, so the bundles must not be submitted before that command is real.
4. **It does not make the repository public.** It makes it *publishable*. The remaining gates
   are named in the root [`README.md`](../../README.md) and in
   [`docs/ROADMAP.md`](../ROADMAP.md)'s phase 0, and the largest of them is that the
   private repository's name still appears in twelve published JSON Schema description strings
   and in the generated TypeScript and pydantic output derived from them.
